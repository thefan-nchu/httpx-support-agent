# 设计与评测说明

`app.py` 暴露本机 FastAPI 路由。普通模式使用 `workflow.Investigator` 做确定性检索，证据模式使用 `evidence_workflow.EvidenceInvestigator`。两者共享会话持久化和恢复机制。证据模式的执行顺序是 inspect → retrieve → respond。

- inspect 把用户报告的版本和环境事实写入会话。有版本变更时，记录上一轮编号，带上有效事实和原问题背景。
- retrieve 调用 `grounded_agent.answer_grounded` 获取候选、拟稿和审查。引文须能在对应来源中逐字找到；模型审查只能保留已有条目。重排失败可回退融合顺序。
- respond 保存当轮结论、引文字面和来源索引。各轮 E1 独立解析。复查失败仅保存失败提示，历史证据仍可查询。

评测的三个数字属于不同问题。完整 Hit@5 衡量前五是否找齐参考证据。答复联合达标要求参考事实完整、各结论获支持、处理行为合适，历史评分由同对话模型辅助完成。多轮说明能否保留原场景，以及引文是否能回查，不能替代答复的语义复核或真实故障解决率。

发布版可用 `demo_version_recheck.py` 演示版本变化和引用历史。它用夹具稳定展示同一状态路径，不衡量真实模型表现。普通模式语料仅包含官方文档。版本化证据模式的语料还包含发布说明和精选源码。每份文件在加载时按清单哈希检查。
